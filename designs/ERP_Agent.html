1الغرض والنطاق

Purpose and scope

عربي

تمكين الموظّف من تنفيذ عمله في أوراكل من الميدان عبر جواله، ومن سحب تقارير يملك صلاحيتها، دون إنشاء حساب تكامل جديد، ودون فتح منفذ إلى شبكة المصنع، ودون أن تحمل أي أداة بيانات اعتماده. الموظّف يسجّل دخوله بنفسه في متصفّح ظاهر على صفحة أوراكل الحقيقية، والأداة تنفّذ نصوصاً معتمَدة ومحدودة داخل تلك الجلسة.

خارج النطاق صراحةً: لا مساس بأنظمة التحكّم الصناعي (DCS/PLC)، ولا إنشاء سلسلة أرقام رسمية موازية، ولا استبدال لأي وظيفة في أوراكل. المنصة تُكمِّل نظام تخطيط الموارد ولا تحلّ محلّه.

English

To let an employee complete his Oracle work from the field through his phone, and pull reports he is already entitled to, without a new integration account, without an inbound port into the plant network, and without any tool holding his credentials. The employee signs in himself, in a visible browser, on the genuine Oracle page; the tool executes approved, bounded scripts inside that session.

Explicitly out of scope: no contact with industrial control systems (DCS/PLC), no second official numbering series, and no replacement of any Oracle function. The platform complements the ERP; it does not substitute for it.

الجملة التي تُلخّص الضمانة كلّها · The one sentence that carries the assurance

«الأداة لا تستطيع فعل شيء لا يستطيعه صاحب الجلسة بيده، ولا أن تتصرّف باسم غيره، ولا أن تعمل على صفحة لم تتعرّف عليها يقيناً.» وكل جملة منها مفروضة بآلية قابلة للفحص: صلاحية أوراكل نفسها، وحارس الجلسة، وتحقّق الهدف.

“The tool can do nothing the signed-in person could not do by hand, cannot act as anyone else, and cannot act on a page it has not positively identified.” Each clause is enforced by a mechanism a reviewer can test: Oracle's own authorisation, the session guard, and the target assertion.

And because Fusion has a documented REST API that does the same work, UI automation here is the weaker choice.

A · الهوية والمصادقة — Identity and authentication

IDالمتطلّبRequirement
A1الأداة لا تطلب ولا تخزّن ولا تعرض حقلاً لبيانات اعتماد أوراكل إطلاقاً. المستخدم يكتبها بنفسه في صفحة أوراكل الحقيقية داخل متصفّح ظاهر.The tool never requests, stores or renders a field for Oracle credentials. The user types them himself into the genuine Oracle page inside a visible browser.
A2المحرّك يرفض تنفيذ أي خطوة على صفحة مصادقة (دخول، تحقّق ثنائي، تغيير كلمة مرور) أو على أي صفحة تحوي حقل كلمة مرور.The engine refuses every step on an authentication page (sign-in, MFA, password change) or on any page containing a password input.
A3لا يُحقَن نصّ المحتوى قبل أن يطابق العنوان نمط ما بعد الدخول؛ فقبل تلك اللحظة لا تملك الأداة وصولاً إلى الصفحة أصلاً.No content script is injected before the URL matches a post-login pattern; before that moment the tool has no access to the page at all.
A4النافذة تعرض شريط العنوان الحقيقي وحالة TLS والقفل، فلا يتعارض التطبيق مع تدريب التوعية بالتصيّد.The window shows the real address bar, TLS state and padlock, so the application does not contradict phishing-awareness training.
A5تُفعَّل مصادقة ويندوز المدمجة حيث تتوفّر فلا يُكتب حقل كلمة مرور أصلاً — وضبطها بسياسة سجلّ على الجهاز تنشرها تقنية المعلومات (AuthServerAllowlist وAuthNegotiateDelegateAllowlist تحت مفتاح WebView2)، ولا يمكن للتطبيق ضبطها بنفسه: معاملات المتصفّح الإضافية توقّفت عن العمل في إصدار التشغيل 110 فما فوق.Windows Integrated Authentication is enabled where available, so no password field is typed at all — configured by a machine registry policy that IT pushes (AuthServerAllowlist and AuthNegotiateDelegateAllowlist under the WebView2 key). The application cannot set it itself: additional browser arguments stopped working in Runtime 110 and later.
A6الاقتران بإجراء الدخول القائم في المنصة: تفتح الأداة صفحة دخول CementOps المعتادة بتحقّقها الثنائي، فيستعمل الموظّف ما يعرفه ولا يتعلّم إجراءً جديداً. ويبقى QR أو OTP بديلاً للأجهزة المشتركة والأكشاك. وفي الحالتين يُربط الجهاز وتُلغى الصلاحية مركزياً من صفحة الأجهزة.Pairing uses the platform's existing sign-in: the tool opens the familiar CementOps login with its MFA, so the employee uses what he already knows and learns no new procedure. QR or OTP remains the fallback for shared devices and kiosks. Either way the device is bound and access is revoked centrally from the devices page.
A7رمز الاقتران قصير الأجل، لمرة واحدة، ومربوط بالمستخدم والجهاز معاً.The pairing code is short-lived, single-use, and bound to both the user and the device.
A8جلسة الأداة مع المنصة تنتهي بالخمول وتحتاج إعادة اقتران بعد مدّة معلنة.The tool's platform session expires on idle and requires re-pairing after a declared period.
A9استمرار الجلسة بلا اعتماد: تُحفظ جلسة أوراكل في ملفّ تعريف WebView2 ثابت كما يفعل أي متصفّح — لا أكثر. والاستطلاع الدوري نشاطٌ طبيعي على الصفحة يمدّ الجلسة ضمن مهلة الخمول التي تضبطها تقنية المعلومات، ولا تُرسل الأداة نبضات صناعية لإبقاء الجلسة حيّة.Session continuity without credentials: the Oracle session lives in a persisted WebView2 profile, exactly as any browser keeps it — no more. Periodic polling is ordinary page activity that extends the session within the idle timeout IT sets, and the tool sends no synthetic keep-alive to hold a session open.
A10اسم المستخدم يجوز حفظه، وكلمة المرور لا. يُحفظ الاسم للتعبئة المسبقة ولمقارنة حارس الجلسة (B8). ولا تُحفظ كلمة المرور ولا رمز التحقق في قرص ولا في ذاكرة ولا مشفّرة — لأن مفتاح فكّ التشفير يكون في الذاكرة نفسها، ولأن التقاطها أصلاً يستلزم قراءة حقل كلمة مرور، وهو ممنوع (A2، A3، D10).The username may be kept; the password may not. The name is kept for pre-fill and for the session-guard comparison (B8). The password and any OTP are never kept on disk, in memory, or encrypted — because the decryption key would sit in that same memory, and because capturing one at all requires reading a password field, which is forbidden (A2, A3, D10).
A11لا استطلاع بلا مهمة قائمة. الاستطلاع يوجد فقط ما دام هناك طلب أوراكل لم يُنجَز؛ فإذا لم تكن هناك مهمة، لا تُحمَّل أي صفحة وتنتهي الجلسة بالخمول كما تنتهي لأي مستخدم. وهذا قابل للاختبار مباشرةً.No poll without an outstanding job. Polling exists only while an Oracle request is unfinished; with no job, no page is loaded and the session idles out exactly as it would for any user. This is directly testable.
A12مدّة الاستطلاع تضبطها تقنية المعلومات لا نحن، ويجوز لهم ضبطها أطول من مهلة الخمول (ICX: Session Timeout) — فتنتهي الجلسة وتنتقل المهمة إلى «بانتظارك». فالميزة تتدرّج ولا تتجاوز الضابط، والمفتاح بيدهم.IT sets the poll interval, not us, and may set it longer than the idle timeout (ICX: Session Timeout) — in which case the session expires and the job parks as "waiting for you". The feature degrades; it never defeats the control, and the dial is theirs.
A13يستمرّ الاستطلاع ما دامت جلسة نظام التشغيل قائمة — بما في ذلك والشاشة مقفلة، لأن القفل هو السلوك الآمن المطلوب من الموظّف ولا يصحّ معاقبته عليه. ويتوقّف فوراً عند انتهاء تلك الجلسة بأي سبب: إطفاء الجهاز، أو إعادة تشغيله، أو تسجيل خروج، أو خروج تلقائي تفرضه السياسة، أو التبديل إلى مستخدم آخر.Polling continues while the OS session is alive — including with the screen locked, because locking is the secure behaviour the employee is required to perform and must not be penalised for. It stops at once when that session ends for any reason: shutdown, restart, sign-out, a policy-enforced automatic logoff, or switching to another user.
A14سقف مطلق للامتداد: لا يمدّ الاستطلاع جلسة أوراكل أبعد من مدّة قصوى معلنة من لحظة الدخول (الافتراضي وردية واحدة). وبعدها تنتهي الجلسة وتنتقل المهمة إلى «بانتظارك» ويحتاج الأمر دخولاً جديداً. فالامتداد محدود لا مفتوح.An absolute extension ceiling: polling never extends an Oracle session beyond a declared maximum from sign-in (default one shift). After it the session ends, the job parks as "waiting for you", and a fresh sign-in is required. The extension is bounded, never open-ended.
A15عند العودة من السكون أو الإسبات يُعاد التحقّق من حارس الجلسة (B8) قبل أول استطلاع — فجهاز نام في مكان وصحا في مكان آخر لا يستأنف بصمت.On resume from sleep or hibernation the session guard (B8) is re-verified before the first poll — a machine that slept in one place and woke in another does not resume silently.
A16مفتاح سياسة لتقنية المعلومات: StopPollingOnLock — فإن فرضته السياسة توقّف الاستطلاع عند القفل واستأنف عند فتحه. القرار سياستهم لا تفضيلنا، والأداة تطيعه بلا نقاش.An IT policy switch: StopPollingOnLock — when their policy requires it, polling stops on lock and resumes on unlock. The decision is their policy, not our preference, and the tool obeys it without argument.

B · الصلاحية — Authorisation and entitlement

IDالمتطلّبRequirement
B1لا يُسمح باستخدام الأداة إلا لمن يملك حساب أوراكل والصلاحيات اللازمة لتنفيذ العمل.Only a person holding an Oracle account and the privileges required for the work may use the tool.
B2كل نص يعلن الصلاحية التي يحتاجها — مسؤولية ووظيفة في EBS، دور وامتياز في Fusion — وتُطابَق بما يملكه المسجَّل بعد دخوله.Every script declares the privilege it needs — responsibility and function in EBS, role and privilege in Fusion — matched against what the signed-in user actually holds.
B3النص الذي لا تتوفّر صلاحيته يُعرض مُعطَّلاً بسبب مكتوب، ولا يبدأ تنفيذاً يفشل في منتصفه.A script whose privilege is absent is shown disabled with a written reason; it never starts an execution that fails half-way.
B4يُتحقَّق من الصلاحية بالقراءة فقط — بفتح الشاشة أو قراءة قائمة المسؤوليات — ولا يُتحقَّق بإنشاء مستند تجريبي وإلغائه.Entitlement is probed read-only — opening the screen or reading the responsibility list — never by creating and cancelling a test document.
B5الأداة لا تبدّل مسؤولية ولا دوراً نيابةً عن المستخدم للوصول إلى وظيفة. لا رفع صلاحية بأي شكل.The tool never switches responsibility or role on the user's behalf to reach a function. No privilege elevation of any kind.
B6يُعاد فحص الصلاحية عند كل تشغيل، لا عند تسجيل الدخول فقط.Entitlement is re-checked on every run, not only at sign-in.
B7يُفحص ما يحتاجه النص فقط؛ ولا تُعدَّد ولا تُخزَّن مجموعة صلاحيات المستخدم كاملة.Only the privilege the script needs is checked; the user's full entitlement set is never enumerated or stored.
B8حارس الجلسة: يُقرأ اسم المستخدم المسجَّل من الصفحة ويُقارَن بالمقترن بالمنصة؛ والاختلاف يوقف التنفيذ. ويُصنَّف ضابطاً كاشفاً وطبقة دفاع ثانية لا ضمانة قاطعة — لأن القراءة من صفحة قابلة للتزوير من الصفحة نفسها وهشّة أمام تغيّر الواجهة. الضمانة الأصلية للنسبة أن الجلسة لمن كتب كلمة المرور (A1).Session guard: the signed-in username is read from the page and compared with the paired user; a mismatch stops execution. Classified as a detective, defence-in-depth control rather than a guarantee — reading from a page is spoofable by that page and brittle under UI change. The primary attribution guarantee is that the session belongs to whoever typed the password (A1).
B9الأداة ترث حقوق المستخدم ولا تغيّرها؛ وفصل المهام يبقى مسؤولية أوراكل ومراجعته.The tool inherits the user's rights and alters none; segregation of duties remains Oracle's responsibility and Oracle's review.

C · حوكمة النصوص — Script governance

IDالمتطلّبRequirement
C1النصوص بيانات يفسّرها مفسّر مشحون داخل الأداة؛ لا eval ولا كود يُحمَّل وقت التشغيل من أي مصدر.Scripts are data, run by an interpreter shipped inside the tool. No eval and no code loaded at runtime from any source.
C2مفردات مغلقة: Set · Get · Click · WaitFor · Assert فقط. لا ملفات ولا حافظة ولا شبكة ولا انتقال إلى عنوان حرّ من داخل النص.Closed vocabulary: Set · Get · Click · WaitFor · Assert only. No file, clipboard or network access, and no arbitrary navigation, from inside a script.
C3كل نص موقّع على الخادم، والأداة ترفض غير الموقّع أو المعدَّل؛ والمفتاح العام مثبّت وقت البناء.Every script is signed server-side; the tool refuses anything unsigned or altered; the public key is pinned at build time.
C4دورة اعتماد: مسودّة ← مراجعة تقنية المعلومات ← معتمَد ← منشور. ولا يُشغَّل في الإنتاج إلا المعتمَد، والاعتماد صفّ تدقيق باسم معتمِده.Approval workflow: draft → IT review → approved → published. Only approved scripts run in production, and the approval is an audit row naming its approver.
C5كل نص يعلن الأصل ونمط العنوان المسموح له بالعمل عليه، ويُرفض في غيرهما.Every script declares the origin and URL pattern it may run on, and is refused anywhere else.
C6الجوال يرسل runScript(id, params) فقط ولا يرسل خطوات؛ والمعاملات تُتحقَّق على الخادم مقابل مخطّط معرَّف.The phone sends only runScript(id, params), never steps; parameters are validated server-side against a declared schema.
C7المسجّل غير موجود في نسخة الإنتاج؛ وهو بناء منفصل مقصور على تقنية المعلومات.No recorder is present in the production build; it is a separate build restricted to IT.
C8كل نص يحمل رقم إصدار وبصمة الصفحة التي سُجِّل عليها.Every script carries a version number and the signature of the page it was recorded against.
C9المفسّر نفسه سطح هجوم ويُقيَّم أمنياً: نموذج تهديد مكتوب، واختبار بمدخلات مشوّهة، وسلوك معرَّف عند نصّ غير صالح (رفض لا تنفيذ جزئي).The interpreter is itself an attack surface and is assessed: a written threat model, fuzz testing, and a defined behaviour for a malformed script (reject, never partially execute).

D · سلامة التنفيذ — Execution safety

IDالمتطلّبRequirement
D1لا يبدأ أي تنفيذ قبل التحقّق من أن الصفحة المقصودة موجودة وبياناتها مكتملة.No execution begins until the target page is confirmed present with its data complete.
D2التحقّق بالهوية: نمط عنوان وعنصر مرجعي معروف — لا لقطات شاشة ولا إحداثيات.Verification by identity: a URL pattern plus a known anchor element — never screenshots or coordinates.
D3انتظار «الاستقرار» لا «التحميل»: شرط محدّد ثم فترة سكون قصيرة بلا تغيّر في الصفحة، لأن العرض الجزئي في ADF يسبق وصول البيانات.Wait for settled, not loaded: a specific condition then a short quiet period with no DOM change, because ADF partial rendering precedes the data.
D4تحقّق إلزامي من هوية السجل قبل أي كتابة: الشاشة تعرض المستند المقصود بعينه ورقمه.A mandatory record-identity assertion before any write: the screen shows the intended document and its number.
D5عند تغيّر واجهة أوراكل بعد ترقيع، يفشل النص على بصمة الصفحة قبل كتابة أي حرف.When an Oracle patch changes the UI, the script fails on the page signature before a single character is written.
D6لكل انتظار مهلة معلنة؛ ولا استطلاع بلا سقف.Every wait has a declared timeout; no unbounded polling.
D7الفشل يوقف ولا يعالج: لا محاولة تعافٍ، والصفحة تُترك كما هي، ويُبلَّغ عن التحقّق الذي سقط بأسماء الحقول لا بلقطة للصفحة.A failure stops and does not repair: no recovery attempt, the page is left as it is, and the failed assertion is reported by field name, not by a page capture.
D8خطوة تأكيد قبل التشغيل تعرض ما سيُكتب وأين، والمستخدم يضغط «تشغيل». لا تنفيذ صامت.A pre-run confirmation shows exactly what will be written and where; the user presses Run. No silent execution.
D9قائمة خطوات حيّة أثناء التشغيل، وإيقاف فوري عند انتقال الصفحة أو إخفاء النافذة أو تدخّل المستخدم.A live step list while running, aborting immediately on navigation, window hide or user input.
D10المحرّك لا يكتب في حقل من نوع كلمة مرور بأي حال من الأحوال.The engine never types into a password-type field under any circumstance.

E · بيانات التقارير — Report data handling

IDالمتطلّبRequirement
E1التقارير تُسحب من كتالوج مسمّى معتمَد بمعاملات محدّدة؛ ولا يوجد «تصدير ما على الشاشة».Reports are pulled from a named, approved catalogue with constrained parameters. There is no "export what is on screen".
E2كل مدخل في الكتالوج يعلن تصنيف بياناته، وما يحمل بيانات شخصية (رواتب، طبّي، موارد بشرية) مستبعَد بالسياسة لا بمربّع اختيار.Every catalogue entry declares its data classification; anything carrying personal data (payroll, medical, HR) is excluded by policy, not by a checkbox.
E3النمط الافتراضي هو «تشغيل وإشعار»: الناتج يبقى في أوراكل ولا تخرج بيانات.The default mode is trigger-and-notify: the output stays in Oracle and no data leaves it.

L · دورة حياة النص: التصميم والاختبار قبل النشر — Script lifecycle: authoring and testing before publication

بقية الوثيقة تشترط «نصّاً معتمَداً». وهذه المجموعة تقول أين يُصنع، وكيف يُختبر، ومن يعتمده — وهي نصف الضمانة الذي لا يظهر للمستخدم النهائي إطلاقاً. The rest of the document requires an approved script. This group says where it is made, how it is tested and who approves it — the half of the assurance the end user never sees.

IDالمتطلّبRequirement
L1التصميم يتمّ داخل الأداة نفسها في وضع «مصمّم النصوص»، ولا يُفتح هذا الوضع إلا لمن منحه المسؤول صلاحية Integration.Scripts.Design باسمه. ولا تظهر أدوات التصميم إطلاقاً لمن لا يملكها.Authoring happens inside the tool itself, in a Script Designer mode that opens only for a person the administrator has granted Integration.Scripts.Design by name. The authoring tools are not rendered at all for anyone else.
L2المسجّل يلتقط المراسي من شجرة الوصولية (التسمية والدور والربط) وبصمة الصفحة، ويقترح التحقّقات — ولا يعتمد على إحداثيات ولا على ترتيب بصري.The recorder captures anchors from the accessibility tree (label, role, association) plus the page signature, and proposes the assertions — never coordinates or visual order.
L3لا يُقبل نص للاعتماد بلا تحقّق هوية سجل (D4) وبلا بصمة صفحة (C8). الفحص آلي لا يُترك لانتباه مراجع.No script is accepted for approval without a record-identity assertion (D4) and a page signature (C8). The check is automatic, not left to a reviewer's attention.
L4تشغيل تجريبي جافّ: ينفّذ كل الخطوات ويتوقّف قبل فعل الالتزام الأخير، فيُثبت المسار والتحقّقات بلا إنشاء مستند.Dry run: executes every step and stops before the final commit action, proving the path and the assertions without creating a document.
L5لا يُعتمد نص إلا بعد اجتياز تشغيل كامل على بيئة الاختبار، بنتيجة مسجّلة وتاريخها ورقم المستند الذي أنشأه هناك.No script is approved until it has passed a full run on the test environment, with a recorded result, its date, and the document number it created there.
L6فصل مهام: من سجّل النص لا يعتمده. المسجّل والمعتمِد شخصان مختلفان، ويظهر الاسمان في صفّ التدقيق.Segregation of duties: whoever recorded the script does not approve it. Recorder and approver are different people, and both names appear in the audit row.
L7قبل النشر تُطابَق بصمة الصفحة على بيئة الإنتاج؛ والاختلاف يمنع النشر لأن الاختبار والإنتاج ينحرفان.Before publication the page signature is matched against production; a difference blocks the publish, because test and production drift.
L8كل نشر مربوط برقم طلب تغيير عند العميل، ولا يتمّ بدونه (J9).Every publish is tied to a customer change request number and does not proceed without one (J9).
L9إعادة تحقّق مجدولة لكل النصوص المعتمَدة على بيئة الاختبار، وبعد كل ترقيع أوراكل — فيُكتشف الكسر قبل أن يصطدم به مستخدم.A scheduled re-validation of every approved script on the test environment, and after every Oracle patch, so breakage is found before a user hits it.
L10حالات النص معرَّفة ومغلقة: مسودّة ← مسجَّل ← تحت الاختبار ← اجتاز ← بانتظار الاعتماد ← معتمَد ← منشور ← (مُستبدَل · معلَّق · متقاعد). وكل انتقال مسجَّل بفاعله ووقته.Script states are defined and closed: draft → recorded → in test → passed → pending approval → approved → published → (superseded · suspended · retired). Every transition is recorded with its actor and time.
L11مسار طارئ: يجوز تعليق نص فوراً بلا اعتماد مسبق، ولا يجوز نشره كذلك أبداً. الطوارئ تُوقف ولا تُطلق.Break-glass: a script may be suspended immediately without prior approval; it may never be published that way. An emergency stops things, it does not release them.
L12لكل نص مالك مُسمّى في تقنية المعلومات مسؤول عن صلاحيته بعد كل ترقيع، ويُنبَّه آلياً عند انحراف البصمة.Every script has a named owner in IT accountable for its validity after each patch, alerted automatically on signature drift.
L13وضع المصمّم يعمل على بيئة الاختبار. وعلى الإنتاج يُسمح بالفحص وبناء النص بلا تنفيذ أي Set أو Click — فيُبنى النص حيث لا توجد بيئة اختبار، ولا يُنفَّذ.Designer mode operates against the test environment. On production it permits inspection and authoring with no Set or Click executed — so a script can be built where no test instance exists, but never run there.
L14المصمّم ينظّم عمله في شجرة مجلّدات (مجال ← وحدة ← نص)، ويسمّي النص برمز فريد، ثم يرفعه إلى الخادم بحالة مسودّة. والشجرة نفسها هي كتالوج الخادم.The designer organises work in a folder tree (area → module → script), names the script with a unique code, then uploads it to the server as a draft. The same tree is the server-side catalogue.
L15لغة النصوص مغلقة ومعلنة: دوال محدودة، وثوابت Fields.* وLocations.*، ومتغيّرات بلا أنواع، وقيم افتراضية معلنة (Locations.Right افتراضاً). لا استدعاء ديناميكي، ولا تكرار غير محدود، ولا شبكة ولا ملفات ولا حافظة.The script language is closed and published: a fixed function set, Fields.* and Locations.* constants, untyped variables, and declared defaults (Locations.Right by default). No dynamic invocation, no unbounded iteration, no network, file or clipboard access.
L16المحرّر يوفّر إكمالاً تلقائياً للدوال والثوابت، ولعناوين العناصر المقروءة من الصفحة المفتوحة عبر شجرة الوصولية — فلا تُكتب المراسي من الذاكرة ولا تُخمَّن.The editor provides autocomplete for functions and constants, and for the element labels read from the open page through the accessibility tree — so anchors are never typed from memory or guessed.
L17منقّح كامل: تشغيل، إيقاف مؤقّت، تنفيذ خطوة، ونقاط توقّف. وعند التوقّف يُبرَز العنصر المستهدف على الصفحة الحقيقية، فيرى المصمّم ما سيلمسه السطر قبل تنفيذه.A full debugger: run, pause, step in, and breakpoints. On a pause the target element is highlighted on the real page, so the designer sees what the line will touch before it runs.
L18سجلّ التشغيل وسجلّ الأخطاء في شبكة واحدة: الوقت، رقم السطر، الفعل، الهدف، النتيجة، المدّة، ودرجة الخطورة — قابلة للتصفية على الأخطاء وحدها.Run log and error log in one grid: time, line number, action, target, result, duration and severity — filterable to errors alone.
L19نصوص التقارير للقراءة فقط: كل خطواتها قراءة وتنقّل، والكتابة مقصورة على حقول معاملات التقرير المعلنة. ويُفحص هذا آلياً قبل الاعتماد — أي Set خارج المعاملات يمنع الاعتماد.Report scripts are read-only: every step is a read or a navigation, and writing is confined to the declared report parameter fields. This is checked automatically before approval — any Set outside the parameters blocks it.

M · دورة حياة تقرير طويل الأمد — Long-running report job lifecycle

التقرير في أوراكل ليس فعلاً واحداً بل أربعة أطوار قد تمتدّ ساعات: إرسال يُرجع رقم الطلب، ثم انتظار، ثم فحص حالة، ثم تنزيل وتحميل. وهذا يحوّل الأداة من مشغّل نصوص إلى منسّق مهام دائمة. A report in Oracle is not one act but four phases that may span hours: submit returning a request id, then waiting, then a status check, then download and load. That turns the tool from a script runner into a durable job orchestrator.
